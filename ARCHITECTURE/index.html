    clef v3 - architecture & API contract¶

    This file is the contract between the server modules, the backends, the CLI, the web console, the clients and the tests. Change it first, then the code.

    Package layout¶

    pip install / uv tool install installs two packages from src/ and one console script, clef.

    Module Owns
    clef_server/__init__.py __version__; calls backend.prepare_environment() once (torch-free, before any torch import)
    clef_server/config.py Config dataclass from CLEF_* env vars, VERSION, MODEL_REPO/MODEL_REVISION, parse_api_keys
    clef_server/paths.py state dir, log/pid files, classifiers dir, resolve_model_path(cfg) (never downloads)
    clef_server/dotenv.py optional .env loading: ./.env then ~/.config/clef/env fill os.environ before Config is built (non-empty set variables win, empty counts as unset; only CLEF_* and GEMINI_API_KEY are taken, other names are ignored with a warning naming them; CLEF_ENV_FILE overrides, empty disables, and is read from the real environment once per process, so a file cannot redirect loading); called by config.load(), cli.main and doctor; the server logs the loaded file names (never values) at startup
    clef_server/backend.py the only place with device-specific code: detection, dtype, sync, OOM, memory, telemetry, preflight, quantization config (bitsandbytes / torchao), device memory cap, pinned host copies (HostCopier)
    clef_server/offload.py CPU offload: plan_layers (which decoder layers stay on the host) and LayerStreamer (async copy-in per forward); pure logic plus a copier supplied by backend.py
    clef_server/engine.py background model load (load_model: standard, quantized or offloaded), single GPU worker thread, micro-batching, length bucketing, warmup
    clef_server/schemas.py pydantic v2 SystemOne request/response models + strict validation
    clef_server/classify.py classification API models + translation classify/score <-> SystemOne records/answers
    clef_server/classifiers.py saved-classifier store (ClassifierStore on db.py: versions, owner, audit; one-time import of v3.1 JSON files)
    clef_server/security.py multi-key auth, per-key rate limiting, CORS setup
    clef_server/logs.py stdlib-only logging: text / JSON formatters, the request-id context, secret redaction for the access log, uvicorn's log_config
    clef_server/media.py data-URL / (optional) URL fetching with SSRF guard + caps, image/video decode
    clef_server/stats.py request log ring buffer, latency histogram, counters, forward stats, time series ring buffer
    clef_server/appctx.py AppContext: what a feature module gets from create_app() (config, stats, engine, auth / rate-limit dependencies, inference helpers, lifecycle hooks)
    clef_server/main.py FastAPI app factory create_app(cfg, engine), core routes, middleware, error mapping, FEATURES (feature modules mounted on the context), run(cfg)
    clef_server/compat.py, compat_openai.py, compat_hf.py, compat_schema.py, compat_errors.py OpenAI (/v1/models, /v1/chat/completions) and Hugging Face zero-shot (/hf/models/{id}) routes; JSON-schema -> questions translation; client-shaped errors
    clef_server/evaluation.py metric math (compute_metrics), POST /v1/evaluate and /v1/evaluate/metrics, the evaluate job kind
    clef_server/jobs.py, clef_server/webhooks.py async jobs (database store, the priority / fair-share / off-hours scheduler, /v1/jobs* routes, built-in kinds) and signed, SSRF-guarded webhook delivery
    clef_server/jobsort.py F2, opt-in: length sort inside a job window and tokenize-ahead for jobs (see Job throughput)
    clef_server/cli.py the clef command (serve/stop/status/logs/doctor/download/bench/open/version); download is a pinned, resumable snapshot_download with a disk-space check
    clef_server/doctor.py environment checks per backend, including a recommended memory setting; main(argv) -> int
    clef_server/httpbench.py the async HTTP load test (clef bench; bench/http_bench.py is a shim)
    clef_server/static/ Clef Console (zero-build Preact + htm SPA, vendored uPlot; screens in screens/) served at /
    clef_client/ sync + async Python client (httpx), typed classify results
    clients/js/ dependency-free ESM JS/TS client (fetch), Node 18+ and browsers
    clef_server/db.py Database (SQLAlchemy Core engine from CLEF_DATABASE_URL), transactions, Alembic upgrade, jobs.db→clef.db copy, URL redaction, audit() helper
    clef_server/dbschema.py the SQLAlchemy MetaData and every Table in this document (one place; migrations mirror it)
    clef_server/migrations/ Alembic env.py, script.py.mako, versions/NNNN_*.py
    clef_server/models/ base.py (DecisionModel, LocalTensorAdapter, Capabilities, ModelSpec, UnknownModel), registry.py (clef.models entry points, CLEF_MODEL), clef_release.py (clef-flash, clef 27B)
    clef_server/keystore.py principals, hashed keys, key cache, quotas (Quotas), on db.py; shared by the server and clef keys
    clef_server/admin.py feature module: /v1/whoami, /v1/admin/keys*, /v1/admin/audit
    clef_server/schedule.py pure off-hours window maths for the job scheduler (Window, parse_window; DST rules); the Scheduler itself is in jobs.py
    clef_server/cache.py in-memory LRU result cache used by Engine.prepare / Engine.submit
    clef_server/router.py, clef_server/review.py, clef_server/llm.py feature module: routers, label-set versions, the Review routes (/v1/routers*, /v1/review*); review.py is the store of the review and llm_calls tables; the OpenAI-compatible LLM client
    clef_server/batches.py feature module: OpenAI /v1/files* and /v1/batches* on the batch job kind

    Invariants (unchanged from v2): - ONE uvicorn worker per process (one model adapter, one model), ONE thread ever touches the GPU (the engine worker). - Python >=3.10 (the WSL venv is 3.10): no typing.Self, tomllib, ExceptionGroup or other 3.11+ features. - Never edit files in the model directory; wrap or re-implement in the engine.

    Configuration (config.py)¶

    All settings come from env vars. The CLI flags of clef serve set the same env vars.

    Env Default Meaning
    CLEF_MODEL_PATH unset release dir. Unset: ~/models/clef-flash if it holds a release, else the pinned HF cache snapshot
    CLEF_MODEL_REPO / CLEF_MODEL_REVISION Cloudflare/clef-flash / pinned sha what clef download fetches and the cache lookup uses
    CLEF_DEVICE auto auto, cuda, rocm, mps, cpu (cuda:1 / rocm:1 select an index)
    CLEF_DTYPE auto auto, bfloat16, float16, float32 (auto: see backend dtype rules)
    CLEF_QUANT none none, int8, nf4. int8: bitsandbytes on CUDA, torchao on ROCm / MPS / CPU. nf4: bitsandbytes only (CUDA, and ROCm where it is not recommended); refused elsewhere with a clear error
    CLEF_QUANT_BACKEND auto auto, bnb, torchao: the library behind CLEF_QUANT (auto: CUDA keeps bitsandbytes, everything else torchao; nf4 is bitsandbytes only)
    CLEF_OFFLOAD none none or cpu: keep the embeddings and the layers that do not fit under the device budget in host RAM and stream them in per forward (CUDA and ROCm; a warning and no effect on MPS / CPU, which share one memory pool)

    CLEF_CORS_ORIGINS empty comma-separated allowed origins (* allowed); empty = CORS off

    CLEF_SAMPLE_INTERVAL_S 2 gauge sampling period for the time series (memory, telemetry, queue)
    CLEF_INTERACTIVE_BURST 8 interactive micro-batches in a row before waiting background (job) work gets one; >= 1

    Backend interface (backend.py)¶

    class BackendError(RuntimeError): ...       # unavailable explicit device, unsupported quant/dtype combination
class PreflightError(RuntimeError): ...     # not enough free memory for the chosen dtype/quant (clear message)

def prepare_environment(environ: MutableMapping[str, str] = os.environ) -> list[str]:
    """Torch-free. setdefault() the per-platform env BEFORE torch is imported. Returns the names it set.
    - torch build is ROCm (importlib.metadata version of torch contains "+rocm"):
        TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1, and on WSL (/dev/dxg exists) HSA_ENABLE_DXG_DETECTION=1;
        PYTORCH_TUNABLEOP_* unless CLEF_TUNABLEOP=0 (on by default). HSA_* / AOTriton are NEVER set on other backends.
    - macOS: PYTORCH_ENABLE_MPS_FALLBACK=1.
    - everywhere: HF_HUB_OFFLINE=1 is NOT set here (the CLI download needs the network; the engine passes
      local paths so it never downloads)."""

def detect(requested: str = "auto") -> Backend:
    """auto: cuda (NVIDIA: torch.cuda.is_available() and torch.version.hip is None) > rocm (torch.version.hip)
    > mps (torch.backends.mps.is_available()) > cpu. An explicit request that is unavailable raises BackendError
    with a hint (wrong torch build, driver missing, HSA_ENABLE_DXG_DETECTION on WSL, ...)."""

@dataclass
class Backend:
    name: str                     # "cuda" | "rocm" | "mps" | "cpu"
    device: torch.device          # cuda:N for cuda AND rocm, mps, cpu
    def synchronize(self) -> None
    def empty_cache(self) -> None
    def is_oom(self, exc: BaseException) -> bool       # torch.OutOfMemoryError / cuda OOM / MPS "out of memory"
    def device_name(self) -> str                       # "NVIDIA GeForce RTX 4090", "Apple M3 Max", CPU brand
    def memory(self) -> dict                           # see below; never raises
    def telemetry(self) -> dict                        # see below; never raises, "unavailable" elsewhere
    def resolve_dtype(self, requested: str) -> tuple[torch.dtype, str | None]   # (dtype, warning or None)
    def versions(self) -> dict                         # {"torch","cuda","hip","driver","macos"} (None if n/a)
    def fast_path(self) -> dict                        # {"causal_conv1d": bool, "fla": bool, "expected": bool}

def preflight(backend: Backend, dtype: torch.dtype, quant: str, weights_gb: float,
              cap_gb: float = 0.0, offload: str = "none") -> list[str]:
    """Raise PreflightError when free memory (or the CLEF_MAX_DEVICE_MEMORY_GB cap) is clearly below what the load
    needs; return warnings when close. With offload=cpu on cuda / rocm the engine plans the split itself and only
    the cap is checked here."""

def quant_method(backend: Backend, quant: str, choice: str = "auto") -> str:
    """"bnb" or "torchao". auto: nf4 -> bnb; int8 -> bnb on cuda, torchao on rocm / mps / cpu.
    An explicit choice wins (nf4 + torchao is a BackendError)."""

def quantization_config(backend: Backend, quant: str, dtype: torch.dtype, choice: str = "auto") -> Any | None:
    """None for "none". Else a transformers config: BitsAndBytesConfig (int8 / nf4; cuda and rocm only) or
    TorchAoConfig(Int8WeightOnlyConfig) with the embeddings and the vision tower left in bf16. BackendError with
    an install hint when the library is missing or the backend cannot run it."""

def recommend_memory_setting(backend: Backend, weights_gb: float = 19.0) -> str | None:
    """One line of advice from the detected memory (printed by `clef doctor`); None when bf16 fits."""

    Offload support on Backend: has_discrete_memory (true on cuda / rocm), pin_host(tensor), host_copier() (a HostCopier that copies pinned host tensors on a side stream) and apply_memory_cap(cap_gb) (torch.cuda.set_per_process_memory_fraction; returns whether a limit was set). ACTIVATION_RESERVE_GB = 2.5.

    Dtype rules (resolve_dtype("auto")): bf16 on cuda (if torch.cuda.is_bf16_supported(), else fp16 + warning), rocm, and mps on macOS >= 14 (fp16 + warning before 14); cpu: bf16 when the CPU supports it, else fp32. An explicit dtype the device cannot run falls back the same way with a warning. Any fallback must be validated for probability parity against bf16 (bench/parity.py, results in docs/hardware-results.md).

    memory(): {"kind": "vram"|"unified"|"system", "total_gb", "allocated_gb", "reserved_gb", "free_gb"} (floats or None). cuda/rocm: torch.cuda.mem_get_info/memory_allocated/memory_reserved; mps: torch.mps.current_allocated_memory, driver_allocated_memory, recommended_max_memory; cpu: process RSS and system memory (psutil if installed, else None).

    telemetry(): {"available": bool, "source": "nvml"|"amdsmi"|"rocm-smi"|None, "util_pct", "temp_c", "power_w", "mem_used_gb", "mem_total_gb"}; values None when unknown. Imports pynvml / amdsmi lazily; failures are logged once at debug level and turn the result into {"available": false, ...}. rocm-smi (subprocess) results are cached for >= 2 s. Under WSL (measured, 7900 XTX) amdsmi gives utilization + temperature only; its VRAM usage is impossible (> total) and is dropped.

    Engine interface (engine.py)¶

    Record = dict  # sanitized: {"model": str, "state": Any, "questions": dict,
               #             "images": list[PIL.Image.Image] | None, "videos": list[np.ndarray] | None}

class EngineNotReady(RuntimeError): ...          # -> HTTP 503
class InputTooLarge(ValueError): ...             # -> HTTP 413 (e.g. schema alone exceeds max_tokens)
class GpuOutOfMemory(RuntimeError): ...          # -> HTTP 503 (after backend.empty_cache())

class Engine:
    def __init__(self, cfg: Config, stats: Stats, loader: Callable | None = None,
                 backend: Backend | None = None): ...
        # loader: test injection; default resolves the model dir (paths.resolve_model_path) and imports
        #   joint_schema_model from it. backend: test injection; default backend.detect(cfg.device),
        #   done on the worker thread at load time (so a BackendError becomes status "error", not a crash).
    status: str             # "loading" | "warming" | "ready" | "error"
    error: str | None
    load_seconds: float | None
    def start(self) -> None
    async def decide(self, records: list[Record], priority: str = "interactive") -> list[Result]
        # results in input order; priority is "interactive" (default) or "background" (ValueError otherwise)
    def info(self) -> dict
    def sample(self) -> dict    # cheap gauges for the time series, see below; never raises; any thread
    def shutdown(self) -> None

    Before the backend is detected (status == "loading" early) backend is null and the gpu block has available: false. gpu keeps the v2 key names for compatibility; on mps memory_kind is "unified" and vram_total_gb is recommended_max_memory; on cpu available is false. info() must stay fast (< 5 ms): it returns the cached telemetry from the last sample().

    sample() -> {"mem_used_gb": float|None, "mem_total_gb": float|None, "gpu_util_pct": float|None, "gpu_temp_c": float|None, "gpu_power_w": float|None} (memory = allocated on cuda/rocm/mps, RSS on cpu).

    Rules (v2 rules kept): - Exactly ONE thread ever runs forwards (the worker). decide() enqueues and awaits futures. - Text-only records are coalesced for up to batch_window_ms / max_microbatch, grouped by length bucket, one forward per group, right-padded to the next pad_multiple. Media records run alone, unpadded. - Two priority lanes: interactive (everything through ctx.infer, and direct engine.decide() calls) and background (ctx.decide: jobs, the evaluate job kind). Each lane is FIFO. The worker waits for the first item of either lane, lets the batch window run, and only then picks the lane for the micro-batch, so an interactive item that arrives during a window opened by background work still goes first. A micro-batch holds ONE class: interactive whenever any is queued (up to the starvation bound below), else background. Micro-batching and bucketing work as before inside it. - Classes are not mixed even when the micro-batch has room. The model is compute-bound (batching adds ~30% throughput), so an interactive record riding in a batch of 8 background records pays nearly the whole batch's forward time; running it alone first costs the job one extra host overhead (~50% of a single forward). - Starvation bound: after CLEF_INTERACTIVE_BURST (default 8) interactive micro-batches in a row while background work was waiting, the next micro-batch is background. A steady interactive load therefore leaves jobs at least 1 of every N+1 micro-batches. A micro-batch already taken is never preempted: all of its groups (one forward per length bucket, one per media record) run before the worker looks at the lanes again. - Warmup: one forward per bucket (<= 1024) at batch sizes {1, max_microbatch}; status "warming" meanwhile. - No torch.cuda.* outside backend.py. OOM: backend.is_oom(exc) -> backend.empty_cache() -> GpuOutOfMemory; the worker keeps running. Timing uses backend.synchronize(). - Load order on the worker: detect backend -> resolve dtype -> resolve model path -> preflight (if enabled) -> load_model(...): apply the device cap (CLEF_MAX_DEVICE_MEMORY_GB), build the quantization config, then either the standard path (load_release_model(path, device=..., dtype=..., quantization_config=...), kwarg only when quantizing) or, with CLEF_OFFLOAD=cpu on cuda / rocm, an offloaded load. Each failure becomes status "error" with a one-line actionable message. - Offloaded load (offload.py): token and output embeddings (~4 GB) stay on the host and are gathered on the CPU; decoder layers beyond the device budget (cap or free memory, minus ACTIVATION_RESERVE_GB) are held in pinned host memory, spread evenly through the stack, and copied in on a side stream one or two layers ahead of the compute; the vision tower, final norm, rotary tables and the joint head stay on the device. The weights are the same tensors, so probabilities are identical to a normal run. After a failed forward the streamer puts the layers back on the host. Measured numbers: memory.md. - The engine reports stats.record_forward(...) and stats.set_queue_depth(n, by_class={"interactive": i, "background": b}) (n = i + b, the v2 total).

    Classification API (classify.py, classifiers.py)¶

    The classification routes are a thin, stable layer over the SAME engine: each input is translated into exactly one SystemOne record (the same record /v1/systemone would build), so probabilities are identical to the equivalent SystemOne call (verified live within 1e-3). All of them are POST inference routes (logged, rate limited, counted in stats) and return usage, timing and request_id like the existing routes.

    Labels: either a list of unique non-empty strings (["billing", "technical"]) or an object label -> description ({"billing": "Payments or invoices"}); 2..max_labels labels for single-label, 1..max_labels for multi-label.

    Translation (normative - the live parity test rebuilds these exact records): - single-label -> questions = {"label": {"type": "choice", "criteria": C, "instructions": I}} where C = {l: l for l in labels} for a list, the object as given for a dict, and "instructions" is present only when the request has instructions. - multi-label -> one noul question per label, question id = the label: {"type": "noul", "instructions": P + 'Does the label "<label>" apply?'} where P = instructions + " " when given, else ""; plus "criteria": {"true": desc} when labels is a dict and desc != label. - score -> questions = {"score": {"type": "score", "criteria": levels, "instructions": I}} (instructions only when given). - state = input verbatim (string or any JSON); images/videos pass through load_media exactly as on /v1/systemone; model is optional (omitted or null = the served model; another id is 404).

    Async jobs and webhooks (jobs.py, webhooks.py)¶

    Guide: jobs.md.

    • POST /v1/jobs {kind, payload, webhook?, metadata?} -> 202 with the job and Location: /v1/jobs/{id}. The payload is fully validated at submit (400 with a path); an unknown kind lists the available ones. Kinds: classify, score, systemone (jobs.py) and evaluate (evaluation.py). 409 + Retry-After when CLEF_MAX_JOBS is reached.
    • GET /v1/jobs?status&kind&limit&offset (newest first), GET /v1/jobs/{id} (status, progress, ETA, result summary, webhook delivery status), GET /v1/jobs/{id}/results (JSON pages with next_offset, or a full stream with ?format=ndjson|csv; CSV neutralises cells starting with =, +, -, @), POST /v1/jobs/{id}/cancel, DELETE /v1/jobs/{id} (409 while queued or running).
    • Storage: the database (ctx.db: SQLite <state_dir>/clef.db or CLEF_DATABASE_URL; jobs, payloads, result rows, webhook deliveries; see Storage). Statuses: queued, running, succeeded, failed, cancelled, interrupted. Jobs are scheduled by class and fair share (see Job scheduler), at most CLEF_JOB_ACTIVE at a time, and ONE micro-batch in flight across all of them (CLEF_MAX_MICROBATCH records through ctx.decide), so interactive requests interleave. A job interrupted by a stop or crash resumes after its last stored row on the next start. Rows are appended in one transaction that reads done inside it, so an in-flight chunk is either stored whole or recomputed (no gap, no duplicate). A clean stop (lifespan shutdown) parks the running job as interrupted without counting it; only a job found still running at startup (a crash) increments resumes, and more than CLEF_JOB_MAX_RESUMES crashes fail it. A job whose cancel was requested before the stop or crash ends cancelled at that point (or at the next start), never resumed. Cancel is atomic per state: JobStore.cancel_queued (queued / interrupted -> cancelled), else JobStore.flag_cancel in one transaction (running -> cancel_requested=1; interrupted, i.e. parked meanwhile by a stop or runner error -> cancelled at once), so a park racing the cancel cannot drop it. Every terminal transition (finish, cancel while queued or interrupted, cancel / give-up at recovery) writes the status and the pending terminal webhook record in ONE SQLite transaction, so a crash cannot lose the event. A row the engine rejects becomes an {"index", "error"} row; the job fails only on systemic errors (engine down for CLEF_JOB_ENGINE_WAIT_S). Finished jobs are purged CLEF_JOB_TTL_HOURS after they finish.
    • Ownership: with auth on, a job belongs to the key name that submitted it. Another non-admin principal gets 404 (not in its list either); a key without the jobs scope gets 403; admins see every job, owner-less ones (created while auth was off) included.
    • Webhooks: events job.succeeded, job.failed, job.cancelled (default) and opt-in job.progress (at most one per 10 s, one attempt). Headers X-Clef-Event, X-Clef-Delivery, and with a secret X-Clef-Timestamp and X-Clef-Signature: sha256= HMAC-SHA256 of "<timestamp>.<raw body>". 2xx = delivered; 408 / 425 / 429 / 5xx and network errors retry with exponential backoff up to CLEF_WEBHOOK_ATTEMPTS; other statuses and all redirects are final. A delivery still pending at restart is retried with the same delivery id, but its attempt count and backoff start over (known behaviour). Disabled until CLEF_WEBHOOK_ALLOW is set; the allow-list is checked at submit and on every attempt, the host is resolved then and the connection is pinned to the checked IP (see SECURITY.md).
    • Jobs are not counted in /v1/stats or the request log (they use ctx.decide).
    • Custom kinds: ctx.extra.setdefault("job_kinds", {})[name] = {"validate": fn, "run": async_fn, "resumable": bool} (see jobs.md).

    GET /readyz¶

    Readiness for load balancers and orchestrators (open, like /livez). 200 {"ready": true} only when the engine status is ready and the app is not draining; otherwise 503 {"ready": false, "status": "loading|warming|error|draining", "error": <engine error or null>}. Unlike /health, warming is not ready. Draining: uvicorn closes its listening sockets and drains connections BEFORE the lifespan shutdown runs, so a flag set there is never seen by a client. main.run therefore serves through DrainingServer (a uvicorn.Server subclass): the FIRST SIGTERM / Ctrl-C sets app.state.draining = True and keeps serving for CLEF_DRAIN_S seconds (/readyz answers 503 draining, every other route works as usual), then calls uvicorn's own handle_exit and the normal shutdown starts. A second signal during the drain skips the rest of it; after that uvicorn's semantics apply (another Ctrl-C forces the exit). CLEF_DRAIN_S=0 (default) stops at once, as before. The lifespan still sets draining = True first thing at shutdown, for launchers other than main.run (plain uvicorn). A drain only helps a load balancer that probes /readyz faster than it lasts: probe interval x failure threshold must be below CLEF_DRAIN_S, and CLEF_DRAIN_S below the supervisor's stop timeout (Docker sends SIGKILL after 10 s by default; clef stop waits 30 s). Liveness stays on /livez (process up); the Docker HEALTHCHECK uses /readyz with a long start period so a container whose model failed to load turns unhealthy.

    Logging (logs.py)¶

    • setup_logging(fmt) installs one root handler (idempotent; a later call only swaps its formatter). run(cfg) passes uvicorn_log_config(fmt) to uvicorn.run(log_config=...), so the foreground clef serve and the --detach child (python -m clef_server.main) log the same way.
    • CLEF_LOG_FORMAT=text (default): the app keeps "%(asctime)s %(levelname)-7s %(name)s %(message)s", uvicorn keeps its own formatters. json: the app, uvicorn / uvicorn.error and uvicorn.access all write one JSON object per line: {"ts": "<ISO 8601 UTC, ms>", "level", "logger", "msg"} plus "request_id" when the record is emitted inside a request (a ContextVar set by GuardMiddleware; the access line is logged inside it) and "exc" (the formatted traceback) when there is one. Stdlib only.
    • Redaction: RedactSecretsFilter rewrites the values of the key, api_key and token query parameters to REDACTED in every string of record.args (keeping the args tuple's shape, which uvicorn's AccessFormatter unpacks) and in record.msg. It parses each ?query (up to #, whitespace or "): the query is split on & and a parameter is redacted when its name, percent-decoded (as auth reads it) and lower-cased, is one of the three, so k%65y= and KEY= are masked and step_key= is not; every other parameter stays byte-identical. It sits on uvicorn's handlers (via log_config), on clef's root handler and, from the lifespan, on the uvicorn.access logger, which covers servers started with plain uvicorn.     Build contract (v3.2)¶

    The sections below were the contract for the v3.2 build waves (C to F) and are now built: storage, models, keys, cache, review and router, the job scheduler, files and batches, job throughput.     Rules shared by every section below: - One clef server per database (D3).     Engine setup: - SQLite: a QueuePool of file connections; a connect event sets journal_mode=WAL, synchronous=NORMAL, foreign_keys=ON, busy_timeout=30000; writes are serialised by the tx() RLock + BEGIN IMMEDIATE. A new file is created 0600 on POSIX. - Postgres: pool_size=CLEF_DATABASE_POOL_SIZE, max_overflow=pool_size, pool_pre_ping=True. At open, a dedicated connection (its own NullPool engine, libpq TCP keepalives keepalives=1, keepalives_idle=10, keepalives_interval=5, keepalives_count=3; never a pooled connection) takes pg_try_advisory_lock(1667032422) and holds it for the process lifetime; a second server on the same DB fails with DatabaseError("another clef server holds this database (one server per database)"). The CLI commands do not take the lock. - Lock heartbeat (Database.start_heartbeat, started by the lifespan): a daemon thread checks every 10 s, on the lock connection, SELECT 1 FROM pg_locks WHERE locktype = 'advisory' AND pid = pg_backend_pid() AND objid = <key> AND granted (an error counts as lost: the session, and so the lock, is gone). When lost, a second server may already own the DB: it logs CRITICAL, sets lock_lost (tx() then raises DatabaseError, claim_next returns None) and exits the process with status 3 at once (os._exit: no shutdown hooks, which would write), so a supervisor restarts it; the restarted server takes the lock again or stops at startup. - open_database is called once in create_app and published as ctx.db. JobStore, ClassifierStore and the later stores receive it; nothing else opens connections. The lifespan closes ctx.db after the shutdown hooks (runner.stop no longer closes the store).

    jobs.db → clef.db (only when CLEF_DATABASE_URL is unset): if <state_dir>/clef.db does not exist and <state_dir>/jobs.db does, jobs.db is copied, never changed in place. Open it with sqlite3 (timeout 1 s), set PRAGMA locking_mode=EXCLUSIVE and run BEGIN EXCLUSIVE; COMMIT (the lock then lasts until close and fails while any other connection, such as a v3.1 server still running, has the file open). If that fails: DatabaseError("jobs.db is in use by another process; stop the old server first"), and nothing is touched. Otherwise remove a stale clef.db.tmp, copy with the sqlite3 online backup API into a new 0600 clef.db.tmp (it reads through jobs.db-wal), fsync it, os.replace it to clef.db and fsync the directory. Then close jobs.db (SQLite checkpoints and removes its WAL) and rename it jobs.db.migrated (.migrated.N if taken; a leftover -wal follows it as jobs.db.migrated-wal, a -shm is deleted). Logged once at INFO. Idempotent: with no jobs.db there is nothing to do. When both files exist: a WARNING, and clef.db is used.

Memory is about the budget (default 256 MiB at most; typical entries are 1-2 KB so 10000 entries are tens of MB). - Thread-safe (threading.Lock); in memory only, lost on restart. No invalidation: the questions and the model ref are in the key, and the engine also clears the cache when its model loads. - A hit returns a copy of the stored result with usage as stored (the original input_tokens) and timing = {"queue_ms": 0, "forward_ms": 0, "batch_size": 0, "cached": true} (main adds total_ms). Computed records carry "cached": false. timing.cached is the per-record hit marker for quotas and the request log. Probabilities are bit-identical to the stored forward. - Bypass: a request with Cache-Control: no-cache (case-insensitive token anywhere in the header) skips the lookup and still stores the fresh result. ctx.infer reads the header and passes cache=False down (ctx.decide(..., cache=False) -> engine.prepare(records, cache=False)); background callers pass it explicitly. - Identical records inside one call are computed once; the later ones are filled from the first after the forward and are marked as hits and counted as hits in the stats (Prepared.dups; Prepared.slice turns a dup whose source was sliced away into a miss). - Only successful forwards are stored (submit stores them even if a sibling failed). Errors, OOM and media records are never cached. - Quotas (contract decision 3): cache hits do not count. D1 charges only the results whose timing.cached is false. The request log and stats count the request as usual. - /v1/stats gains "cache": Engine.cache_stats() + {"hit_rate"}. The engine registers cache_stats with Stats.set_cache_source at construction; Stats.snapshot reads it. hit_rate = hits / (hits + misses). - Memory: about 2 KB per entry for a 10-option question (measured, ~20 MB for 10 000 entries); more questions or options scale it linearly.

    Env: CLEF_CACHE_SIZE (Configuration). Tables: none. Routes: none (header only). Error codes: none.

    Invariants: a cache entry is only ever written from a successful forward of the same process; media records never hit the cache; the key never contains secrets or the API key.

    Trigger (per routed item, under the active label set with n options including other): - other wins → reason other, buffered. - top probability < τ(n) → reason low_confidence, buffered. τ(n) rises with the label count: 0.5 for n <= 10, 0.7 for 11-30, 0.85 for 31-64 (defaults; tuned on tickets_labelled.csv, per-router override config.gate.thresholds = [[10, 0.5], [30, 0.7], [64, 0.85]]). - top two within config.gate.margin (default 0.15) → reason ambiguous, review item, not buffered. - "Buffered" = a review row kind=item, state=buffered with the input stored (D17). The other label's description names the other labels in negative form up to 15 labels, then a generic sentence.

    Buffering and calls: a flush happens when a router has CLEF_ROUTER_BATCH (20) buffered items, when the oldest buffered item is CLEF_ROUTER_FLUSH_S old, or on POST .../propose. One call in flight per router and one globally. The prompt carries the current labels and the buffered inputs truncated to CLEF_ROUTER_MAX_INPUT_CHARS, numbered (members are returned as indices, never as copied text), and asks for at most min(3, capacity) new labels. Capacity = min(config.max_labels, CLEF_MAX_LABELS - 1) real labels; at the cap no call is made. Response schema: {"proposals": [{"name", "description", "member_indices", "nearest_existing", "duplicate_of", "rationale"}], "covered_by": [{"index", "label"}], "unclear_indices": [int]} (strict; name matches NAME_RE, description <= 15 words).

    Acceptance test (before a proposal is shown or activated): build the candidate set (current + proposal + other), re-classify the proposal's members with ctx.decide; it passes when at least max(2, 50%) land on the new label with p >= τ(n'). It fails as a duplicate when most land on one existing label. Human labels feed it: a member a human already labelled with an existing label counts against the proposal, and resolving an item with a label re-classifies its text under the active set before the text is purged, recording agreement in the item's prediction.recheck.

    Review mode: passing proposals become review rows kind=proposal, state=open with the acceptance numbers. Auto mode: a passing proposal is activated at once, at most CLEF_ROUTER_MAX_NEW_PER_DAY labels per UTC day (beyond that it waits as a review row). Activation = new router_label_sets version → ClassifierStore.put → re-route the buffered items in the background; an item that still fails the gate gets reroutes += 1, and after 2 it becomes permanent_other (out of future batches; its input is set to NULL in the same statement, D17, since nothing reads it again; input_sha256 and the prediction stay).

    Cold start: a router with no seeds has no label set (clef needs >= 2 options). Every routed item is answered other with reason cold without a forward, and buffered. At CLEF_ROUTER_COLD_BATCH (20) items one bootstrap call proposes 3-8 labels (maxItems 8); the result is one proposal row holding the whole starter set (approve all, or edit, at once). One seed is enough to start the normal loop ([seed, other]).

    Low-confidence items from saved classifiers: ClassifierDef gains review_threshold: float | None (0..1, default None = off). On interactive single-label runs (POST /v1/classifiers/{name}[/batch], not jobs), a result with confidence < review_threshold creates a review row kind=item, reason=low_confidence, router=NULL with the input, in the classifier owner's queue. Only runs by the owner or an admin (auth off counts as admin) are captured: another key's run of the classifier is not captured at all, because storing it under the owner would hand that key's input text to the owner, and the caller cannot act on another owner's classifier review. A classifier with no owner (made while auth was off) is then captured only for admins. Media inputs are never captured.

    Job scheduler¶

    Module boundary: all in jobs.py (JobRunner + a Scheduler class). Kinds keep their validate / run signatures; scheduling happens per chunk inside decide_resilient, which every built-in kind (and evaluate, the batch kind) already uses. A custom kind that calls ctx.decide directly bypasses the scheduler; the contract is that kinds call job.decide(reqs) (= decide_resilient(ctx, job, reqs)).

    Policy: - Classes, strict between classes: urgent (3) > high (2) > normal (1, default) > low (0). Aging: a waiting job's effective class rises one level per CLEF_JOB_AGING_S without a turn, never to urgent. - Fair share inside a class: stride scheduling per owner (principal name; NULL = one owner). pass += cost / weight, weight 1 for everyone in v3.2, cost = the chunk's records. The next turn goes to the lowest pass; an owner that comes back sets pass = max(own, current minimum). "Comes back" = goes from no runnable job to runnable: a new job, or a job leaving a pause (its window reopened, a slot came free); the minimum is over the owners that were runnable already (vtime when there are none), and an un-paused job's aging clock restarts, so a pause never banks turns. Within one owner: higher class first, then interrupted, then seq. State is in memory and rebuilt after a restart. - Turn gate: await scheduler.turn(job) before every engine call of a job; scheduler.done(job, cost) after. The gate wraps each engine call inside decide_resilient (so a bisected chunk takes one turn per call and no turn is held while a job waits for an unavailable engine). One job chunk in flight across all jobs (as today): interactive work still goes first through the engine's lanes. A unit test asserts the background lane never holds more than one job chunk. - Active set: up to CLEF_JOB_ACTIVE jobs are claimed (JobStore.claim(job_id), chosen in stride order) and run as their own asyncio tasks; all of them show running (D9). runner.current becomes a set; progress webhooks are per job. claim(job_id) returns the claimed row (plus claimed_from) or None; claim_next stays for tools and tests but the runner no longer uses it. An urgent job does not wait for a free slot (it is admitted at once, even above CLEF_JOB_ACTIVE), or the class would mean nothing while four normal jobs run. Candidates are ordered like turn waiters (class after aging, owner pass, jobs the owner already runs, interrupted, seq). - Fair slots: when no slot is free and a job of another owner waits for one (queued in its window, or running and paused active_limit), an owner holding more than its share (ceil(CLEF_JOB_ACTIVE / owners wanting slots), at least 1; urgent jobs hold no counted slot) gives up its youngest job (highest seq; among over-share owners, the one holding most). The victim finishes its chunk in flight, then stays running with waiting_reason: "active_limit" (D9: like a job paused off-hours, it keeps its task, its progress and its quota reservation; nothing is parked or re-claimed) and gets the next free slot. A job of a higher effective class than the waiter never yields, an urgent job never yields, and a waiter whose owner already holds its share takes nothing. A single owner with nobody waiting still uses every slot. A free slot goes first to the waiting job whose owner holds the fewest. So CLEF_JOB_ACTIVE bounds the jobs taking turns, not the job tasks. - Windows: schedule = {"window": "HH:MM-HH:MM", "tz": "<IANA>"} per job (default CLEF_JOB_WINDOW in CLEF_JOB_TZ). start > end crosses midnight; start == end = 24 h. Aware datetimes via zoneinfo; on DST days an edge inside the skipped hour starts at the next valid minute, the repeated hour uses fold=0; an instance whose two edges fall in the same skipped hour is empty that day, and next_start skips it (it returns only a moment contains accepts). A job gets turns only inside its window. A queued job outside it stays queued; a running job that leaves it stays running but gets no turns and frees its active slot. Both show waiting_reason: "off_hours" and next_window_at. Unknown tz or a bad window: 400 at submit. - urgent: true needs the urgent scope (403 otherwise), sets class urgent and ignores the window. - Expiry: expire_after_s counts from eligible_at (the first moment the job could take a turn, i.e. when its window first opens; D19). An expired job stops between chunks and ends cancelled with error = "expired" (no new status; JobInfo.expired: true). - Quota at submit, in this order: idempotency lookup (a replay returns the existing job and is not charged) → validate / snapshot → ctx.quotas.reserve(principal, total) (in memory; 429 when it does not fit) → JobStore.create(..., quota_day, quota_reserved). If create raises (JobsFull, an idempotency race that returns another job, a DB error), the reservation is refunded in full before the error is returned. The whole job is charged to the submit day; on cancelled / failed / expiry, total - done is refunded to that day. Env principals and auth off: no reservation. Cache hits are not charged (D23 #3): each chunk's hits (Prepared.hits from ctx.prepare) are handed back to the reservation once the chunk's rows are stored, and quota_reserved drops by the same number in that transaction, which also adds them to jobs.hits (migration 0003). Credited hits are capped at what is still reserved, and exactly the credited number goes back to the quota. The final refund of a cancelled / failed job is quota_reserved - done + hits, read from the row, so it is exact after a restart too; a non-resumable job that restarts from 0 resets hits with its rows.

    Job throughput: window sort and tokenize ahead (F2, jobsort.py)¶

    Opt-in, both default off (CLEF_JOB_SORT_WINDOW, CLEF_TOKENIZE_AHEAD), benchmark-gated (bench/sort_check.sh). run_chunked and the evaluate kind build a jobsort.windowed(ctx, n, build, decide_resilient) once per run; it is None with both flags off, and then the original loop runs unchanged. - A step is one window: CLEF_JOB_SORT_WINDOW items (never fewer than CLEF_MAX_MICROBATCH), or one micro-batch when only tokenizing ahead. The caller builds the window's requests and calls sorter.decide(job, start, reqs), which returns results in the same order as reqs. - decide encodes the whole window with ctx.prepare (CPU threads), orders the records that need a forward (no cache hit, no in-window duplicate) by (is_media, token length), stable, and queues them with ctx.decide_prepared(priority="background") in micro-batches of CLEF_MAX_MICROBATCH: one micro-batch in flight, as before; interactive work still goes first through the engine lanes. Hits and duplicates are put back as Engine.submit would (timing.cached). - Persistence: the caller persists the whole window in one add_items in input order. Rows stay contiguous 0..done-1; a crash, clean stop or cancel inside a window leaves done at the window start (at most one window is recomputed on resume; the resume point need not be window aligned). Progress and the circuit breaker advance once per window. - Tokenize ahead: after window k is encoded, a task encodes window k+1 while k is on the GPU. One GPU worker only. The prefetch looks the cache up before window k's results are stored, so a duplicate in the next window is computed again (same row content, only cache statistics differ). - Errors: a failed prefetch or encode, or a micro-batch the engine rejects (ValueError, OOM, not ready), is re-run through decide_resilient for just those records, so isolation, bisection and the engine wait behave as without the flags. Cancel is checked between micro-batches. - Scheduler: each micro-batch takes a turn (JobHandle.engine_prepared, the gated hand-off) and the window's cache hits are noted on the handle (not charged); the fallback goes through decide_resilient, also gated.

CREATE TABLE batches (
    id                TEXT PRIMARY KEY,           -- "batch_" + the job id's 20 hex
    job_id            TEXT NOT NULL UNIQUE REFERENCES jobs(id) ON DELETE CASCADE,
    owner             TEXT,
    endpoint          TEXT NOT NULL,              -- "/v1/chat/completions" | "/v1/classify" | "/v1/score"
    input_file_id     TEXT NOT NULL,
    output_file_id    TEXT NOT NULL,
    error_file_id     TEXT NOT NULL,
    completion_window TEXT NOT NULL,              -- "24h"
    metadata          TEXT,
    errors            TEXT,                       -- JSON list of {code, line, message, param} (status failed)
    created_at        DOUBLE PRECISION NOT NULL,
    cancelling_at     DOUBLE PRECISION
);
    Input content lives on disk at <state_dir>/files/<id>.jsonl (path built only from a validated id, streamed to a temp file with the size cap, then renamed). Output and error files are virtual: their content is streamed from the job's rows. They live as long as the job (CLEF_JOB_TTL_HOURS); input files until expires_at (expires_after or CLEF_FILE_TTL_HOURS).

    Routes (scope jobs; owner-scoped, admins see all; integer unix-second timestamps):

    Route Request Response
    POST /v1/files multipart: file (.jsonl), purpose=batch, optional expires_after[anchor]=created_at, expires_after[seconds] (3600..2592000) FileObject
    GET /v1/files?after&limit=20&order=desc&purpose {"object": "list", "data": [FileObject], "first_id", "last_id", "has_more"}
    GET /v1/files/{id} FileObject
    DELETE /v1/files/{id} {"id", "object": "file", "deleted": true}; output / error files: 400 (delete the batch's job instead)
    GET /v1/files/{id}/content the JSONL bytes, application/jsonl, streamed
    POST /v1/batches {"input_file_id", "endpoint", "completion_window": "24h", "metadata"?, "clef"?: {"priority", "urgent", "schedule"}} Batch
    GET /v1/batches/{id} Batch
    GET /v1/batches?after&limit=20 limit 1..100, newest first cursor list as for files
    POST /v1/batches/{id}/cancel Batch (cancelling or cancelled)

    FileObject: {"id", "object": "file", "bytes", "created_at", "expires_at", "filename", "purpose", "status": "processed", "status_details": null}.

    Batch: {"id", "object": "batch", "endpoint", "errors", "input_file_id", "completion_window", "status", "output_file_id", "error_file_id", "created_at", "in_progress_at", "expires_at", "finalizing_at", "completed_at", "failed_at", "expired_at", "cancelling_at", "cancelled_at", "request_counts": {"total", "completed", "failed"}, "metadata", "model", "usage": {"input_tokens", "input_tokens_details": {"cached_tokens": 0}, "output_tokens": 0, "output_tokens_details": {"reasoning_tokens": 0}, "total_tokens"}}. request_counts.completed = done - failed; usage.input_tokens = jobs.tokens; model = spec.id; expires_at = eligible_at + 24h (always set: the scheduler sets eligible_at at submit, to the next time the window opens). The SDK's extra_body={"clef": {...}} lands as the top-level clef field.

    Mapping to jobs (one batch = one job of kind batch, visible in GET /v1/jobs?kind=batch; submitted through JobRunner.submit(..., expire_after_s=86400); the batch kind spec itself sets "completed_if_all_failed": True): - Create validates at submit, in the threadpool: the file exists, belongs to the caller and has purpose=batch; every line is JSON with a unique custom_id, method == "POST" and url == endpoint; at most min(CLEF_MAX_BATCH_LINES, CLEF_MAX_JOB_ITEMS) lines. A structural failure creates the batch with status failed and errors.data = [{code, line, message, param}] (no job runs), as OpenAI does. A body that fails translation (prepare_chat / classify / score validation) becomes an error-file line, not a batch failure. endpoint outside the three: 400 param: "endpoint". stream: true in a body: an error line.

    Job state Batch status
    validation failed (no job) failed
    queued, running, interrupted in_progress (cancelling once a cancel was requested)
    succeeded completed
    failed (systemic) failed, errors.data = [{"code": "server_error", "message"}]; rows so far are still served
    cancelled, error = "expired" expired
    cancelled cancelled

    Rows: {"index", "custom_id", "status_code", "body" | "error", "input_tokens"}. Output file line = {"id": "batch_req_<20hex>_<index>", "custom_id", "response": {"status_code": 200, "request_id", "body"}, "error": null} for 2xx rows; the error file streams the non-2xx rows (OpenAI error body) plus, for a finished job, {"response": null, "error": {"code": "batch_expired" | "batch_cancelled", "message"}} for every input line with no row (custom ids re-read from the input file). Output order is input order.

    Limits: CLEF_MAX_FILE_MB (body limit of POST /v1/files only, applied in GuardMiddleware), CLEF_MAX_BATCH_LINES, CLEF_FILE_TTL_HOURS; metadata <= 16 pairs, keys <= 64 chars, values <= 512 chars; completion_window must be "24h". Rate limit (ctx.limited) on POST /v1/files and POST /v1/batches. Quota: the batch reserves its line count at create (Job scheduler).

    Errors (OpenAI shape): 400 invalid_request_error (bad purpose, endpoint, window, metadata, file not .jsonl), 403, 404 (unknown or foreign file / batch), 409 (CLEF_MAX_JOBS), 413 (file too large), 429 (rate_limit_exceeded / insufficient_quota).

    Invariants: files are never in the DB; virtual files never exist on disk; deleting a batch's job deletes its batch and output / error file rows; the batch path uses the same translation as the live routes, so probabilities match /v1/chat/completions.

    As built (F1; clarifications and deviations from the text above, nothing else changed): - prepare_chat(body, cfg, model) takes the served model id the caller already resolved (served_model; its UnknownModel is the route's 404, a model_not_found line in a batch). render_chat(chat, result, request_id, total_ms=None) returns the non-streaming body; chat_outcome returns the parts the streaming route also needs. - jobs.py was touched in three places the contract did not list: JobStore.add_items sums the rows' input_tokens into jobs.tokens (an explicit tokens= count wins); the circuit breaker ignores rows that carry a 4xx status_code (a bad batch line is the client's mistake, still counted in jobs.failed); _execute honours completed_if_all_failed. Each exists once, in jobs.py. - Defaults: CLEF_MAX_FILE_MB 200 (OpenAI's limit), CLEF_MAX_BATCH_LINES 50000, CLEF_FILE_TTL_HOURS 720. - A structurally failed batch still needs the batches.job_id foreign key, so it gets a terminal failed job row (kind batch, payload {}, nothing reserved, never runnable) written in the same transaction as the batch. - output_file_id / error_file_id are null until usable: the batch ended, and the output file has a success / the error file a failed or never-run line. A batch that failed validation has neither. - Clarification: an input file that an unfinished batch references cannot be deleted (409) and is skipped by the TTL purge, because the error file re-reads the custom ids from it. After the batch ended the input file may go; the error file then omits the lines that never ran. - Clarification: admins list, read and delete every file and batch, but POST /v1/batches only accepts an input file the caller uploaded (404 otherwise). The batch job re-checks that the file's owner is the job's owner when it runs, so POST /v1/jobs {"kind": "batch"} cannot read another key's file. The job's quota reservation is the file row's lines, never the payload's. - A line nested too deeply for the JSON parser (RecursionError) is an invalid_json_line like any other bad JSON (and an error row if it is met at run time), never a 500. - POST /v1/jobs {"kind": "batch"} gets the same structural scan at submit, through the kind's snapshot hook (submit only, not on every run or resume): a structural problem is a 400 naming the first bad line. It scans only a file owned by the submitter (jobs.SUBMIT_OWNER), so it never describes another key's file; POST /v1/batches marks the file it scanned itself (a context variable), so a batch is not scanned twice. - The seam to the scheduler is batches.submit_batch_job, a call to JobRunner.submit with the caller's principal, clef.priority, clef.urgent, clef.schedule and expire_after_s = 86400. It maps ValueError to 400 (a bad option), PermissionError to 403 (urgent without the scope), a model not served to 404, JobsFull to 409 and QuotaExceeded to 429. The scheduler reserves the quota once, at submit, from the input file's stored line count, and sets eligible_at (the submit time, or the next time the window opens), so the batch's expires_at is known from the start: eligible_at + 24h. - The audit actions are batch.cancel and file.delete, as listed in Storage.

    Contract decisions (v3.2)¶

    Confirmed by the user (2026-10-17): 1. Unknown model (C2): 404 model_not_found on every route except the HF path id, which stays ignored. This replaces the clef.ignored behaviour of /v1/chat/completions; update test_compat.py. 2. Classifier owner (C1): enforced. Only the owner or an admin may PUT a new version or DELETE (403 otherwise); anyone with classify may run it. 3. Cache hits and quotas (D1/D3): hits do not count. Only computed records are charged. 4. Multi-day jobs (E1): the whole job is reserved on the submit day; the unprocessed part is refunded to that day on cancel / fail / expiry. 5. Paused jobs (E1): a running job outside its window stays running with waiting_reason: "off_hours". 6. Human labels (E2): the re-check runs at resolve time, before the text is purged. 7. Low-confidence sources (E2): routers, plus saved classifiers with review_threshold, on interactive single-label runs only. 8. Privacy (E2): setting GEMINI_API_KEY is the consent to send up to 500 characters per buffered input. No second switch. 9. clef backup on Postgres (C1): exit 2 with a pg_dump hint. 10. 27B pin (C2): C2 fetches the Cloudflare/clef revision sha from the HF API; doctor warns it fits 24 GB only with nf4. 11. Fair-share weights (E1): 1 for every principal; no weight column.
